# Tune Parameter Experiment

## Purpose

This experiment tunes classical and optimization-based controller parameters on the ideal two-mass comfort-seat plant. Its main role is to provide a reproducible baseline set for later experiments, especially the ADRC baseline used by `control_learning_compare`.

The experiment answers three practical questions:

1. Which ADRC gain set should be used as the active baseline?
2. How strong are model-based MPC and DeePC baselines on the same nominal plant and disturbance?
3. What objective value and response level should later learned controllers be compared against?

This is a simulation-only tuning experiment. It does not collect hardware data, although the DeePC dictionary can be built from the CSV trajectories collected by `hardware_stratified_protocol`.

## Plant Model

The simulated plant is the same nominal two-mass vertical dynamics model used across the project:

```text
state = [x1, v1, x2, v2]
dt = 0.03 s
m1 = 0.67 kg
m2 = 0.85 kg
k1 = 3000.0 N/m
k2 = 135.0 N/m
c1 = 0.0 N s/m
c2 = 6.4 N s/m
voice-coil force limit = +/- 2.0 N
```

The shaker force acts on the lower mass. The voice-coil force acts between the lower and upper masses, with the sign convention implemented in `plant_dynamics()` in `main.py`.

Continuous-time dynamics are integrated by RK4. Each control interval is internally subdivided so that the maximum integration step is:

```text
0.003 s
```

This keeps the simulation stable while preserving the external controller sampling period of `0.03 s`.

## Fixed Disturbance

All candidates are evaluated under the same fixed shaker-side disturbance. By default, `main.py` uses:

```text
duration = 9.0 s
seed = 20260516
dt = 0.03 s
```

The disturbance is generated by:

```text
utils.fixed_disturbance.fixed_shaker_disturbance()
```

It uses the same signal vocabulary as the hardware protocol and is bounded by the shaker hardware range. The generated waveform in the current result file has:

```text
samples = 301
time range = 0.00-9.00 s
minimum force = -7.663 N
maximum force = 8.280 N
```

The actual trajectory is a deterministic mixed-frequency force command. Before scaling, the raw signal is:

```text
d_raw(t) = A_mod(t) * (
    0.58 * multisine(t)
  + 0.28 * up_chirp(t)
  + 0.22 * down_chirp(t)
)
```

The multisine component uses six fixed tones:

| Frequency [Hz] | Weight | Phase [rad] |
|---:|---:|---:|
| 0.75 | 0.35 | 1.5591 |
| 1.25 | 0.50 | 1.9840 |
| 1.85 | 0.65 | 2.1194 |
| 2.65 | 0.60 | 6.0519 |
| 3.55 | 0.45 | 1.0753 |
| 4.65 | 0.30 | 2.7374 |

The chirp components cover the same comfort-relevant frequency band from both directions:

```text
up_chirp:   0.70 Hz -> 5.00 Hz, phase = 2.9409 rad
down_chirp: 5.00 Hz -> 0.70 Hz, phase = 5.1347 rad
```

The slow amplitude modulation is:

```text
A_mod(t) = 1 + 0.18*sin(2*pi*0.35*t + 4.7738)
```

After summation, a smooth start/stop envelope with `0.6 s` ramp duration is applied. The waveform is then uniformly scaled to a target peak of:

```text
0.92 * 9 N = 8.28 N
```

Finally, the first and last samples are forced to exactly `0 N`. This makes the trajectory a repeatable broadband shaker excitation with no hard step at the beginning or end.

A copy is written to:

```text
data/fixed_shaker_disturbance.csv
```

## Controller Candidates

The search includes four controller families.

| Method | Candidate count | Description |
|---|---:|---|
| Passive | 1 | zero voice-coil force |
| ADRC | 631 | extended-state observer plus displacement/velocity feedback |
| MPC | 72 | no-preview nominal MPC with projected-gradient box-constrained action optimization |
| DeePC | 55 | regularized least-squares DeePC with measured CSV Hankel dictionary |

The full default sweep therefore evaluates:

```text
759 candidates
```

The default run can be capped for quick checks by passing:

```text
--max-variants N
```

### ADRC Search

ADRC uses the payload displacement and velocity states with an extended disturbance estimate. The nominal input gain is:

```text
b0 = 1 / m2
```

The sweep varies:

```text
observer bandwidth omega_o in {3.5, 4, 5, 6, 8, 10, 12, 14, 16}
feedback pairs (kp, kd) in 10 predefined levels
b0_scale in {0.55, 0.70, 0.85, 1.00, 1.15, 1.30, 1.50}
```

One hardware-like ADRC candidate is also included explicitly.

### MPC Search

MPC uses the nominal discretized plant model. It receives the current shaker disturbance but no future disturbance preview. The forecast is therefore the current disturbance repeated across the horizon.

The random search varies:

```text
horizon in {3, 4, 5, 6, 8, 10, 12, 14}
q_x2 in [2.5e4, 8.0e5] log scale
q_v2 in [4.0e2, 2.0e4] log scale
r_u in [2.0e-3, 1.5e-1] log scale
r_du in [1.0e-2, 1.2] log scale
```

The action sequence is solved by projected gradient descent with `120` iterations and the same `+/- 2 N` force limit as the plant.

### DeePC Search

DeePC builds Hankel matrices from:

```text
../hardware_stratified_protocol/data/trajectory_*.csv
```

The measured dictionary contains the channels:

```text
u = voice_force_n
d = shaker_force_n
y = [x1_filtered, v1_filtered, x2_filtered, v2_filtered]
```

The random search varies:

```text
t_ini in {3, 4, 5, 6, 7, 8}
n_f in {3, 4, 5, 6, 8, 10}
max_columns in {32, 48, 64, 80, 100, 120}
regularization weights over log-scale ranges
state/action objective weights over log-scale ranges
action_alpha in [0.30, 0.95]
```

If a DeePC controller cannot initialize or solve, it falls back to the stabilizing feedback law implemented in `fallback_action()`. The current best DeePC result does not use fallback steps.

## Objective

Every candidate is simulated on the same disturbance and scored by the mean per-step weighted cost:

```text
J = mean(
    180*x2^2
  +   6*v2^2
  +   2*a2^2
  + 0.04*u^2
  + 0.08*du^2
)
```

where:

- `x2` is payload displacement;
- `v2` is payload velocity;
- `a2` is reconstructed from the finite difference of `v2`;
- `u` is the clipped voice-coil force;
- `du` is the step-to-step action change.

Lower objective is better. The best candidate per method is selected by this objective.

## Outputs

Running:

```text
python main.py
python plot.py
```

generates:

```text
data/fixed_shaker_disturbance.csv
data/tuning_summary.csv
data/best_by_method.csv
data/comparison_rollouts.csv
figures/tune_parameter_comparison.pdf
```

`tuning_summary.csv` contains all candidates sorted by objective. `best_by_method.csv` contains one selected candidate for each method. `comparison_rollouts.csv` stores the time histories of the selected candidates and is the source of the comparison figure.

## Role In The Full Study

This experiment should be treated as a baseline tuning stage, not as the final controller evaluation. It uses an ideal nominal plant and a single fixed shaker disturbance. The selected ADRC gains are later reused as the classical active baseline and as the base controller for residual learning. Hardware realism and robustness are evaluated in the downstream DDM, control-learning, hardware-stratified, and actuator-disturbance experiments.
